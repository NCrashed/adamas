# Настоящие потоки: что измерено и чем воспроизводится

Трек E волны 3 Фазы 7 (`docs/phase7-wave3-plan.md`). Три числа, три команды.

## Условия

| что | значение |
|---|---|
| хост | Intel Core i7-12700H, 6 P-ядер + 8 E-ядер, glibc, Linux 6.18 |
| привязка | `taskset -c 8` — один логический процессор P-ядра |
| компилятор | `gcc -std=c11 -O2 -flto -fwrapv -ffp-contract=off` |
| оценка | **пол** выборки; стороны чередуются внутри одного окна |
| машина | **не тихая**: параллельно шли другие агенты, и абсолютные числа с
записанными в `workload-gap/` не сравнимы |

Из-за последней строки все три замера — **парные**: сравниваются два бинаря,
собранных из одной программы и различающихся ровно одной правкой рантайма, и
прогоны их чередуются. Отношение от помехи защищено тем же, чем защищён второй
столбец таблицы разрыва: помеха попадает обеим сторонам поровну.

## 1. Цена места вызова промоушена — 1.41 раза

Единственное число, воспроизводимое **без скрипта**:

```sh
nix develop --command bash -c \
  "cargo test -p adamas-codegen --test threads the_promotion_at_spawn_costs \
   -- --nocapture --test-threads 1"
```

Печатает три числа: однопоточный круг без промоушена, он же с промоушеном
(рантайм собирается дважды, обе стороны верны) и та же программа на четырёх
воркерах. Четыре прогона дали **1.440, 1.407, 1.404, 1.283** и **0.400, 0.407,
0.442, 0.400**.

Нагрузкой из таблицы разрыва это мерить не на чем: ни одна из пяти её программ
питомника не заводит. Разбор — в шапке самого теста.

## 2. Куда ставить снятие пометки разделяемости — 1.497 против 1.000

```sh
nix develop --command bash -c \
  'bash docs/measurements/threads/array-flag-placement.sh'
```

Граница §5.2 «запись в уже разделённый объект» закрывается снятием пометки у
уникального массива. Поставленная в `adamas_array_writable` — то есть на
**общем** пути записи, — она стоила колонной строке 4а **1.497 раза** (1.4974 и
1.4984). Перенесённая в `adamas_array_put`, куда плоский массив не доходит
вовсе, — **1.021** и **0.998**.

Скрипт меряет обе развилки разом: собирает три рантайма (без правки, с правкой
в `put`, с правкой в `writable`) и гоняет их чередованием.

## 3. Гибридный счётчик вектора evidence — 1.003 при размахе 0.061

```sh
nix develop --command bash -c \
  'bash docs/measurements/threads/evidence-counter.sh'
```

Счётчик вектора стал гибридным (ветвь по флагу плюс вынесенная атомарная
половина), потому что вектор файбера уезжает на чужой воркер вместе с его
кадрами. Нагрузками из таблицы разрыва это не мерится — **ни одна из пяти
кадра не ставит вовсе** (`adamas_kont_push` в их порождённом C ноль
вхождений), — поэтому мерено на самой кадроёмкой из доступных, хендлерном
стенде `benches/native.rs`. Шесть парных замеров: 0.9862, 0.9926, 1.0014,
1.0055, 1.0247, 1.0472 — **медиана 1.003 при размахе 0.061**. То есть эффекта
меньше, чем разброс окна; «ноль» по одному прогону здесь был бы заявкой.

Третий замер второго пункта, снятый этим же скриптом на другой загрузке, дал
`writable/без = 1.5619` при `put/без = 1.0043` — то есть 1.497 не совпадение
окна.

## Что проверяется не временем

Гонка временем не видна вовсе, и оба механизма обнаружения живут в тестах:

- `crates/adamas-runtime/tests/atomic.rs` — потерянное обновление числом;
- `crates/adamas-runtime/tests/race.rs` — `ThreadSanitizer` над стендами;
- `crates/adamas-codegen/tests/threads.rs` — он же над **программой корпуса**,
  плюс ответ и ноль живых блоков на каждом из 24 прогонов.

Последнее не избыточно: единственный настоящий дефект трека — неатомарный
счётчик вектора evidence — стенды не задевали вовсе, и нашёл его счёт живых
блоков на корпусной программе.
