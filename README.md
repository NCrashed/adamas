# Adamas

Research-level прототип функционального языка программирования: dependent types
и линейность в одной системе (Quantitative Type Theory), algebraic effects с
handler'ами, Perceus reference counting с FBIP, регионы памяти и SIMD как
first-class конструкции.

Цель - показать, что systems-friendly семантика достижима без «уходов в C»:
один язык для прикладного функционального кода, системного программирования и
type-heavy research.

**Стадия: Фаза 2.** Программа проходит путь целиком - текст, дерево, термы
ядра, проверка типов: `adamas check` работает на монотипном фрагменте языка.
Исполнения ещё нет, оно Фаза 5. См. [roadmap](adamas-design.md#9-roadmap) - 10
фаз, ~3-5 лет до research-grade прототипа.

## Что уже есть

```
crates/adamas-core        QTT-ядро: термы, вычисление, проверка типов,
                          сборка клауз в дерево разбора, тотальность
crates/adamas-parser      лексер, значимые отступы, разбор, обратная печать
crates/adamas-elab        поверхностный язык в термы ядра; вне TCB
crates/adamas-interp      исполнение термов ядра с хендлерами эффектов
crates/adamas-cli         драйвер `adamas`; из команд §7.1 есть `check`
                          и `eval`
crates/adamas-lsp         заглушка; language server - Фаза 3
crates/adamas-warmup-stlc учебный STLC+HM Фазы 0: лексер, парсер,
                          bidirectional-вывод типов, интерпретатор
```

Что язык принимает сегодня, видно по корпусу
[`tests/golden/`](tests/golden/): программы прогоняются целиком, вместе с
ожидаемым выводом. Коротко - индуктивные семейства с индексами, определения
клаузами с вложенными паттернами и рекурсией, зависимые функции, `let` с
аннотацией, постулаты и владение (`unique data`, `resource` с автоматической
вставкой `drop`). Полиморфизма ещё нет: он упирается в имплициты и
метапеременные на термах.

Элаборация вынесена отдельным крейтом, потому что не входит в TCB: она выдаёт
обычный терм ядра, и корректность его устанавливает `check`.

Warm-up - разминка перед Фазой 1, а не часть будущего компилятора: ядро от
него не зависит. Что из него вынесено - в
[`docs/warmup-retrospective.md`](docs/warmup-retrospective.md).

## Сборка

С Nix (тулчейн и dev-инструменты приезжают сами):

```sh
nix develop
cargo test --workspace --all-targets
```

Без Nix понадобится rustup - версия и компоненты берутся из
`rust-toolchain.toml` автоматически:

```sh
cargo test --workspace --all-targets
```
