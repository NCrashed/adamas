# Обрыв по глубине: сколько выдерживает наименьший поток

Замер трека D волны 4 Фазы 8 (§10 вопрос 187). Один вопрос: какое число можно
записать в язык пределом, чтобы валидный текст не ронял компилятор.

Ответ: **125 звеньев терма**. Ставит порог понижение, а не проверка типов, и
меньше всего его у наименьшего окружения языка - порождённого потока с
умолчательным стеком в два мегабайта, в отладочной сборке.

Стенд снят с дерева: `depth_probe.rs` рядом кладётся в
`crates/adamas-cli/examples/` и собирается
`cargo build --example depth_probe -p adamas-cli`; перебор гоняет `sweep.sh`.

## Условия

| что | значение |
|---|---|
| хост | Linux 6.18, glibc |
| сборка | `cargo build` (dev, `opt-level = 0`) - **она и есть худший случай** |
| поток | `thread::Builder::new().stack_size(N)`, N из аргумента |
| главный поток для сравнения | `ulimit -s` = 8192 KiB |
| вердикт | код возврата процесса: 134 - `stack overflow, aborting` |

Обрыв стека не ловится ни `catch_unwind`, ни `Result`, поэтому перебор идёт
процессом на шаг: `sweep.sh` рядом.

**Почему отладочная, а не release.** Порог зависит от размера кадра, а тот -
от профиля: у одной и той же формы release держит вдвадцатеро больше. Предел,
записанный в язык, обязан быть одним числом для обеих сборок, значит браться
он должен от худшей.

## Окружения языка

Явно стек не задан **нигде**: `rg 'stack_size|RUST_MIN_STACK'` по дереву не
находит ничего, кроме потоков ввода-вывода `lsp-server`, которые элаборации не
видят. Все три окружения унаследованы:

| Окружение | Стек | Кто там работает |
|---|---|---|
| порождённый поток Rust | **2 MiB** | `cargo test`; всякий, кто зовёт крейты из рабочего потока |
| главный поток `adamas` | 8 MiB | `check`, `eval`, `build`, `run` |
| главный поток `adamas-lsp` | 8 MiB | перепроверка буфера (`serve` идёт в главном) |

## Порог по стадиям (2 MiB, форма «унарный литерал», глубина = значение)

| Стадия | Проходит | Роняет |
|---|---|---|
| разбор | не мерится этой формой: литерал - одна лексема | - |
| проверка типов | 208 | 210 |
| машина | >208 | - |
| специализация | >208 | - |
| понижение в C | **134** | **135** |
| понижение в LLVM | **134** | **135** |

Порог ставит понижение. Свидетель, который останавливается на проверке типов,
его не видит - и потому до волны 4 его никто не видел.

## Порог по формам (2 MiB, понижение в C)

| Форма | Последнее проходящее | Звеньев | Стоит звену |
|---|---|---|---|
| `(same (same … x))` - применение | 125 | 125 | 1.00 |
| `[a, b, …]` - `Cons`-цепочка | 133 | 133 | 0.94 |
| `Succ`-цепочка - унарный литерал | 134 | 134 | 0.93 |
| блок из `let` | 177 | 177 | 0.71 |
| строка (3 звена на байт) | 78 байт | 234 | 0.53 |
| вложенный `if` (рвётся на **разборе**, 3 входа на уровень) | 93 | 93 | 1.34 |
| голые скобки (рвутся на разборе, 2 входа на скобку) | 190 скобок | 0 | - |

Звено не единая валюта: разброс двукратный. Предел берётся от самой дорогой
формы - применения.

## Порог по стеку (форма «унарный литерал», понижение в C)

| Стек | Проходит | Роняет |
|---|---|---|
| 1 MiB | 65 | 66 |
| 2 MiB | 134 | 135 |
| 8 MiB | 540 | 545 (между ними не уточнялось) |

Ряд линеен: кадр стоит около 15 КиБ на звено.

## Сколько звеньев на самом деле пишется под пределом

Предел один, а мер две, и вторая режет первую: скобка стоит спуску **двух**
входов, поэтому под пределом в 64 входа скобочная вложенность пишется всего
тридцатью уровнями (ещё четыре входа тратит само тело определения). Формы, не
тратящие спуск, дают все 64: список - звено на элемент при двух входах, спайн
применения - звено на аргумент при одном.

| Форма | Звеньев под пределом 64 |
|---|---|
| список `[a, …]` | 64 |
| спайн `g a1 … an` | 61 (три звена бюджета съедает сигнатура) |
| скобки `(f (f …))` | 30 |

## Сумма: написанное плюс литерал

Слагаемые складываются, поэтому мерить порознь недостаточно. Замер при
написанной вложенности в 64 звена:

| Литерал под 64 звеньями | Проходит | Роняет |
|---|---|---|
| унарный | 65 | 66 |
| строка | 46 байт | 47 байт |

## Поток теста - это и есть 2 MiB

Проверено отдельно, а не принято: временный тест в `cargo test`, без всякого
`stack_size`, показал те же **125 против 126**, что и стенд с явными двумя
мегабайтами. Стенд мерит ровно то окружение, о котором говорит.

## Что корпусу нужно сегодня

Обход `tests/golden` (287 файлов) двумя мерами `adamas-parser`:

| Мера | Максимум | Где |
|---|---|---|
| звенья терма | **30** | `eval/packets.adamas` |
| входы спуска | **26** | `eval/interpreter.adamas` |
| унарный литерал | **100** | `eval/unwind-inner-handler.adamas` (`plus 100 n`) |
| строка | **36** байт | `eval/zlib.adamas` |

Отсюда главный вывод замера: **100 + 30 = 130 больше, чем 126**. Корпус,
сложенный сам с собой, в наименьшее окружение уже не помещается, и потому
вариант (а) вопроса 187 - пределы на каждую форму - сумму закрыть не может ни
при каком делении бюджета.
