# Плотный агрегат: читает ли `load iN` ровно свои байты

Проверка трека C волны 3 Фазы 7 (§4.11). Один вопрос и один положительный
контроль.

LLVM-эмиттер держит плотный агрегат **целым своей ширины**: `Vec3` из трёх
`Float32` живёт как `i96` и уезжает в ячейку колонки им же. Ячейки такой колонки
стоят по адресам 0, 12, 24, а блок кучи кончается сразу за последней. Прочитай
`load i96` шестнадцать байт вместо двенадцати — и последняя ячейка читалась бы
**за концом блока**; ответ при этом не изменился бы ни на одной программе
корпуса, потому что лишние четыре байта в него не входят. То есть ошибка этого
жанра проходит и договор трёх вычислителей, и счётчик блоков.

## Условия

| что | значение |
|---|---|
| инструмент | AddressSanitizer поверх порождённого `.ll`, LLVM 21.1.8 |
| конвейер | `llvm-as` → `llvm-link` с рантаймом → `opt -passes=asan` → `llc` → `clang -fsanitize=address` |
| программы | четырнадцать фикстур корпуса, у которых агрегат либо область доходят до памяти рантайма |
| дата | 2026-09-16 |

```sh
nix develop --command bash -c 'bash docs/measurements/packed-bounds/asan.sh'
nix develop --command bash -c 'bash docs/measurements/packed-bounds/asan.sh --control'
```

## Результат

Все четырнадцать — молчат. Инструментированных мест от 26 до 63 на программу;
число печатается затем, чтобы «молчит» не означало «нечего было проверять».

Положительный контроль — `load i96` подменён на `load i128` у каждого чтения
ячейки — падает: `READ of size 16`, `heap-buffer-overflow ... in fn_1`. То есть
четырёхбайтовый перечит этот стенд **видит**, и молчание на честном выходе есть
утверждение, а не отсутствие проверки.

## Ловушка, на которой первая редакция стенда сломалась

**ASan правит только функции с атрибутом `sanitize_address`.** Порождённый `.ll`
его не несёт — ни один наш проход его не ставит, — и без строки `sed`,
дописывающей атрибут, инструментация не встаёт вовсе. Первая редакция стенда
проходила молча **и на честном выходе, и на контроле с чтением в 64 килобайта за
концом блока**: ноль инструментированных мест, ноль сообщений, зелёный
результат. Жанр тот же, что у разбора LLVM 18, молча принимающего неизвестный
интринсик: инструмент отвечает «всё хорошо» на вопрос, которого не услышал.
