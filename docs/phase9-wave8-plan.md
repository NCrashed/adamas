# Волна 8 Фазы 9: хвостовое применение значения-функции

Волна закрывает §10 вопрос 192 вместе с остатком решения 158 - так, как решил
владелец 2026-10-15: **единое соглашение со средой** (вариант (В)). Всякая
функция и лямбда одного представления берёт скрытый параметр-среду, аргументы и
ответ через границу замыкания не боксируются, и хвостовое применение значения -
даже неизвестного вызываемого - становится хвостовым вызовом через указатель.

Документ самодостаточен: он пишется для сессии, которая разговора не видела.

## Что сегодня

`again n acc = k n acc`, где `k` - значение-функция, роняет процесс на большой
глубине у обоих понижений. С волны 5 Фазы 8 это **названный отказ** («stack
exhausted», код 3), а не сигнал, и свидетель его -
`crates/adamas-codegen/tests/tail.rs`, `an_apply_in_tail_position_refuses_by_name…`:
он покраснеет, когда гарантию дадут, и это ожидаемый сигнал волны.

Форма порождённого C (трек D волны 5 Фазы 8, `docs/phase8-w5-trackD-notes.md`):
аргумент боксируется, `adamas_apply` зовётся по аргументу за раз и отвечает
боксированным `adamas_value`, первая форма докручивает трамплин
`adamas_kont_run`, ответ распаковывается. Пять ячеек кучи на виток.

## Что измерено до волны (2026-10-15)

| Что | Как | Итог |
|---|---|---|
| `musttail` при **разных** прототипах | рукописный C: `call(env, f, n, acc)` хвостом зовёт `f->typed(f, n, acc)`, gcc 15 `-O1` | **10⁸ витков проходят**; gcc берёт дугу, пока аргументы в регистрах |
| то же у LLVM | по построению: `tail call` при `tailcc` гарантирован LangRef'ом и при разных прототипах | не мерено прогоном - мерить на первом же срезе, где это печатается |
| цена лишнего параметра-среды на прямом вызове | рукописный C, 10⁹ вызовов `noinline`, gcc `-O2` | 0,65-0,70 с с ним и без него - **в пределах шума** |
| снятое боксирование при известном вызываемом | трек D волны 5 Фазы 8 | 10⁸ витков, ноль ячеек на виток |

Итог замеров: соглашение со средой **реализуемо** обоими понижениями и
**бесплатно** на горячем пути прямых вызовов. Цена волны - объём, а не время
исполнения.

## Почему волна, а не срез

Карта пути замыканий (2026-10-15) нашла четыре блокера, и **каждый один** не
даёт хвостовой позиции:

1. **Perceus снимает хвост сам.** Вызываемое `Apply` берётся взаймы
   (`perceus.rs`, `applied`), и после каждого применения стоит его `Drop`. Пока
   это так, хвостовой позиции у применения нет ни при каком соглашении.
2. **Мономорфизация неполная - вопреки §4.11.** `adamas-elab/src/mono.rs`
   специализирует только ведущие имплиситы со словарём или модулем; чисто
   типово-полиморфные `apply`, `map`, `foldl` остаются обобщёнными, их параметры
   указательны. Записано §10 вопросом 253.
3. **У лямбды нет типа при понижении.** Параметры получают ящик по умолчанию
   (`lower.rs`, `abstraction`); подсказка есть только у записи (`lambda_hints`).
   Представление замыкания поэтому неизвестно в месте постройки.
4. **Форма вызываемого за указателем неизвестна.** Код замыкания несёт скрытые
   `ev` и `kont` всегда, а первая форма вызывающего докручивает трамплин после
   применения (`adamas_kont_run`) - это работа после вызова.

## Срезы, по порядку

Каждый срез - свой коммит, свой полный гейт, свой замер. Развилки внутри среза
разбираются **по одной** с владельцем (CLAUDE.md, «Один вопрос за раз»), и
цена каждого варианта мерится пробой, а не записывается словами.

### 1. Владение вызываемым в хвостовом `Apply` - сделано (лог 2026-10-15)

Нужен любому варианту. Хвостовое применение потребляет вызываемое: дроп
переезжает либо в код вызываемого, либо до вызова (среда читается раньше).
Развилка среза: кто дропает и как это видит частичное применение
(`adamas_apply` копирует замыкание, а не правит на месте).

Готово, когда: после хвостового `Apply` в IR нет `Drop`, корпус отвечает
прежним ответом, число блоков у свидетелей не выросло.

### 2. Тип лямбды до понижения

Развилка среза: (а) ядро несёт домен у `Term::Lam` либо у элаборированного
применения; (б) понижение выводит представление из ожидаемого типа места
постройки (расширить `lambda_hints` с записи на всё); (в) только через срез 3.
Мерить: у скольких лямбд корпуса представление становится известным.

### 3. Мономорфизация против единого представления

Развилка §10 вопроса 253: (а) довести мономорфизацию до обещанной §4.11 -
специализация по всем типовым имплиситам; (б) единое указательное
представление в обобщённом коде плюс адаптеры там, где плоское замыкание уходит
в обобщённый. Мерить: время сборки корпуса и размер кода у (а), число и цену
адаптеров у (б).

### 4. Соглашение со средой

Типизированный вход в замыкании рядом с обобщённым `adamas_code`: обобщённый
остаётся для рантайма (`fiber.c`, `frame.c` - `#closing`, трамплины колбэка
уровня 2, ветка `SEGMENT` у резумпции-значения) и для частичного применения.
Место вызова при совпавшей в рантайме арности зовёт типизированный вход
напрямую. Раскладка `closure_block` меняется (`_Static_assert` в `closure.c`,
обход в `release.c`/`promote.c`).

### 5. Хвостовой вызов через указатель

`ADAMAS_MUSTTAIL` у C и `tail call tailcc` у LLVM на хвостовом применении.
Свидетель `tail.rs` переворачивается из отказа в 10⁸ витков; `stack.c` меняет
текст отказа; `benches/closure.rs` перемеряется. §6 переписывается по
измеренному.

## Риски, названные заранее

- **Текст порождённого C у корпуса сдвинется целиком.** Снимков его корпус не
  держит; тесты, читающие текст (`flat.rs`, `forms.rs`, `apply.rs`, `tail.rs`),
  поменяются вместе со срезом 4.
- **Упакованный ответ** (`Repr::Packed`) хвостом не идёт ни у одного понижения:
  такие сигнатуры остаются на обобщённом пути.
- **Частичное применение** типизированного входа не берёт: проверка арности
  остаётся рантаймной.
- **`@noalloc`**: источник `Boxing` у применения значения (`adamas-core/src/alloc.rs`)
  меняет смысл после среза 4.
