# Измерение: чего стоит текстовый `.ll`

Основание для развилки волны 0 Фазы 7 (`docs/phase7-plan.md`) — как привязываться
к LLVM: `inkwell`, `llvm-sys` или текстовый `.ll`. У текстового пути две
названные цены, скорость и проверки, плюс заявленная выгода — независимость от
мажора LLVM. Здесь измеряются все три. Проведено 2026-09-08.

LLVM в dev-окружении проекта нет: он нужен только этому измерению, и тянуть его
во `flake.nix` до начала Фазы 7 незачем. Команды ниже берут его разово.

## Скорость разбора

```sh
nix-shell -p llvm clang --run 'bash docs/measurements/ll-path/measure.sh'
```

`gen.sh N` печатает синтетический C из `N` мелких функций, по форме близкий к
выходу наивного кодогенератора после мономорфизации: разбор значения, две
RC-операции, вызов соседа, конструктор, `drop` аргумента. `measure.sh` гоняет по
нему конвейер и печатает долю разбора.

Результат на LLVM 21.1.8, лучшее из трёх прогонов, два независимых запуска: 8–9%
на 200 функциях, 6.3% на 2000, 5.8–6.0% на 20000. Доля падает, потому что разбор
линеен, а оптимизация суперлинейна. Это верхняя граница добавки — построение IR
через API тоже не бесплатно. На 200 функциях счёт идёт на десятки миллисекунд, и
разброс там сравним с величиной; крупные размеры повторяются стабильно.

## Что ловит `llvm-as`

Ловит несовпадение типов, отсутствие терминатора, нарушение доминирования. **Не**
ловит несовпадение арности вызова — и `opt -passes=verify` тоже не ловит, то есть
API-путь не поймал бы. Проверки в обоих случаях делает verifier на прогоне, а не
система типов Rust.

```sh
printf 'declare i64 @g(i64, i64)\ndefine i64 @f() {\n  %%r = call i64 @g(i64 1)\n  ret i64 %%r\n}\n' > /tmp/arity.ll
nix-shell -p llvm --run 'llvm-as /tmp/arity.ll -o /dev/null; echo "exit=$?"'   # exit=0
```

## Привязка к мажору

Матрица чтения `.ll` версиями 18.1.8, 21.1.8, 22.1.8 строго треугольная: новая
читает старый IR, обратно — нет. Но ломает единственный **необязательный** флаг,
`getelementptr inbounds nuw`, появившийся после 18.

```sh
# IR от 21, приведённый к консервативному подмножеству, собирается 18-й
sed 's/getelementptr inbounds nuw/getelementptr inbounds/g' v21.ll > cons.ll
nix-shell -p llvmPackages_18.libllvm llvmPackages_18.clang --run \
  'llc -O2 -filetype=obj cons.ll -o x.o && clang x.o -o x && ./x; echo $?'
```

Сверялось не кодом возврата 0, который получается и случайно: программа
переделана с `acc & 1` на `acc % 251`, обе сборки вернули 30.

**Вывод.** Независимость от мажора текстовый путь даёт, но не даром: нужно
правило «консервативное подмножество IR, новые необязательные атрибуты не
использовать без причины», и проверяется оно прогоном на минимальной
поддерживаемой версии — тем же способом, что MSRV, и по той же причине: греп по
форме атрибута видит половину класса.
