# Трек A волны 4 Фазы 8: примитивы в подключаемом модуле (§10 вопрос 188)

Материал под §13 и §10. Трек меряет и выносит наверх: выбор — расширение
поверхности языка, и принимать его не треку.

## 1. Постановка 188 промахнулась, и промах несущий

188 говорит: «сравнить два числа в модуле, который кто-то подключает, **нельзя
вовсе**». Прогоном это неверно. Ниже — программа из двух файлов, которая
сегодня, на `3261fd5`, проверяется, собирается и считает.

`Lib/Cmp.adamas` — библиотечный модуль, сравнивающий числа и разбирающий
литеральный паттерн:

```adamas
isBig : UInt64 -> Bool
isBig n = ltUInt64 10 n

classify : UInt64 -> UInt64
classify 0 = 100
classify n = n
```

`Main.adamas`:

```adamas
data Bool where
  False : Bool
  True : Bool

import Lib.Cmp (isBig, classify)

pick : Bool -> UInt64 -> UInt64 -> UInt64
pick b x y = if b then x else y

main : UInt64
main = addUInt64 (pick (isBig 20) 1 2) (classify 0)
```

`adamas run` отвечает `101`. То есть мера успеха волны — «библиотечный модуль
сравнивает числа и разбирает литеральный паттерн» — достижима **без единой
правки компилятора**.

Достижима она, однако, правилом, которого нет ни в §4.8, ни где-либо ещё.

**Верхнеуровневые имена входного файла видны внутри всякого модуля, который он
подключает, если объявлены выше строки `import`.** Свидетель без всякого
`Bool`:

```adamas
-- Lib/Leak.adamas
useSecret : UInt64 -> UInt64
useSecret n = addUInt64 n secret   -- `secret` здесь не объявлен и не подключён
```

```adamas
-- leak.adamas
secret : UInt64
secret = 42

import Lib.Leak (useSecret)
```

Проверяется. `Loader::restrict` закрывает подключаемому файлу **префиксы чужих
модулей**, но корневые имена входного файла не закрывает ничем, а
`Elab::reached` последней ступенью лестницы падает в глобальный
`Signature::lookup`.

Отсюда точная формулировка дефекта — она у́же и хуже записанной:

* библиотека, **объявляющая свой** `Bool` или **подключающая** его из другого
  модуля, сравнивать не может — оба имени квалифицированы, а `prim::BOOL`
  ищется голым;
* библиотека, **не объявляющая никакого** `Bool`, сравнивать может — но лишь
  внутри хозяина, объявившего `Bool` выше строки `import`;
* такая библиотека **в одиночку не проверяется**: `adamas check
  proj/Lib/Cmp.adamas` отвечает «имя `Bool` не найдено»;
* переставь `data Bool` **ниже** `import` — и программа перестаёт проверяться,
  причём отказ показывается в **чужом** файле.

То есть цена не в том, что библиотеки нет, а в том, что библиотека получается
не самостоятельной: её проверяемость есть свойство хозяина и порядка строк в
нём. Ровно так и живёт корпус: `tests/golden/eval/zlib.adamas` объявляет `Bool`
в строке 46, **после** импортов в 39 и 41, и оттого `Zlib/Bytes.adamas` статус
`Z_OK` назвать не может — комментарий в нём это и записывает.

## 2. Второе расхождение: подключённое имя заслоняет своё объявление

Проверено прогоном отдельно, потому что от него зависит цена ветки (б).

```adamas
import Std.Prelude (Bool, True, False)

data Bool where
  False : Bool
  True : Bool

own : Bool
own = True
```

`adamas check --type own` отвечает `own : Std.Prelude.Bool`. То есть **импорт,
написанный выше, заслоняет объявление, написанное ниже**, — молча и в обратную
сторону от ordered scoping §4.8 («побеждает ближайшее объявленное»). Причина в
`Signature::written`: у входного файла `scope.own` пуст, поэтому таблица
псевдонимов спрашивается раньше собственных определений, а порядок текста в
`Scope` не записан вовсе.

Следствие, тоже прогоном: та же программа со сравнением отказывает —

```
несовпадение типов: ожидался `Std.Prelude.Bool`, получен `Bool`
```

— потому что `prim::BOOL` нашёл **своё** объявление, а написанное имя
разрешилось в подключённое. Это и есть цена неявной прелюдии: она ставит
псевдоним всякому файлу, а всякий файл корпуса объявляет своё.

## 3. Соглашений по имени больше одного

`Bool` — не единственное имя, которое компилятор ищет голым. Тем же поиском
ищутся:

| Имя | Кто ищет | Голым? |
|---|---|---|
| `Bool`, `True`, `False` | `check::prim_scheme`, `pattern::verdict`, `eval::compared`, `lower`, `total` | да |
| `Flat` | `check::prim_scheme` (операция региона), `elab/flat.rs` | да |
| `Primitive` | `check::prim_scheme` (операция над вектором), `elab/primitive.rs` | да |
| `fromNat` | `elab/expr.rs` (литерал) | да |
| `withNursery`, `spawnDetached` | `codegen/lower.rs::nursed_family` | да |
| `callbackEnv` | `codegen/lower.rs`, `interp/machine.rs` | да |
| `Unit` | элаборация, машина, понижение | **нет** — имя записывается при объявлении (`Signature::unit`) |

Последняя строка важнее прочих: у одного соглашения задача 188 **уже решена**,
и решена не вариантом из списка. `Signature::name_unit` записывает объявленное
имя в точке объявления, и дальше все четверо спрашивают записанное. Значит в
дереве есть пятый вариант, которого 188 не называет.

Смежное, найденное чтением: доктор-комментарий `adamas-cli/src/suite.rs`
утверждает «ядро в том же соглашении смотрит только короткое имя». Это
неверно: `Signature::lookup` сверяет ключ целиком. Комментарий пережил решение.

## 4. Ветка (а): имя-соглашение объявляется в корне

Правка одна — `adamas-elab/src/decl.rs`, `qualify`: имена `Bool`, `True`,
`False`, объявленные в подключаемом файле, квалификацию пути не получают.
**Шесть строк, одно место.** Ни одного из шести потребителей соглашения
(`check`, `pattern`, `eval`, `lower`, `total`, `suite`) трогать не нужно: имя,
которое они ищут голым, голым и объявлено.

Работает: библиотека объявляет свой `Bool`, сравнивает, разбирает литеральный
паттерн, **проверяется в одиночку** (`adamas check projA/Lib/Cmp.adamas` —
«проверено, объявлений 5»), и программа целиком отвечает 101.

Цена измерена прогоном и оказалась запретительной.

* **Модуль перестаёт уметь экспортировать `Bool`.** `import Std.Prelude
  (Bool)` отвечает «модуль `Std.Prelude` не объявляет `Bool`» — имя-то
  объявлено, но в корне, а не под путём. Отказ верен по букве и обманчив по
  делу.
* Оттого падает **сам корпус**: `tests/golden/eval/prelude.adamas` (программа
  из двух файлов, ради которой прелюдия и вынесена) отказывает на строке 17,
  `tests/golden/project` — на строке 12 `main.adamas`, тест `adamas test`
  «чужой `Bool` признан» — на первой строке своего `Test.adamas`.
* Два файла, объявивших `Bool`, сталкиваются: «определение `Bool` уже
  существует». Отказ громкий, но **показан в чужом файле** — виноват вход, а
  подчёркнута библиотека.
* То же для постороннего конструктора: модуль с `data Tri where True : Tri`
  отвергается, потому что `True` занят чужим `Bool`. Имя конструктора
  становится глобально уникальным на всю программу.
* Молча принимается одно, и это худшее: **модуль отдаёт свой `Bool` всей
  программе без всякого `import`**. Правило видимости §4.8 для трёх имён
  отменяется, и узнать об этом из текста программы нельзя.

Гейт (`--no-fail-fast`): **19 упавших тестов на 53 пройденных целях из 106**;
прогон остановлен вручную — ветка отвергнута раньше, чем дошли медленные цели
понижения. Среди упавших `the_corpus_agrees_with_the_interpreter`,
`every_program_evaluates`, `a_project_of_ten_files_checks_and_evaluates`,
`a_module_of_the_corpus_project_checks_by_itself`,
`every_hover_matches_the_driver`, `a_test_may_use_a_boolean_from_another_module`.

## 5. Ветка (д): соглашение ищется тем же поиском, что написанное имя

Варианта этого в 188 нет, и заведён он не из любви к пятому: это **тот самый
ход, каким в дереве уже решена ровно эта задача для `Unit`**. Разница лишь в
том, что `Unit` записывает объявленное имя в точке объявления, а `Bool` нужен
не одному потребителю, а шести, и записанного имени им мало — нужен ответ «как
этот файл видит `Bool`».

Отсюда формулировка: `Signature::convention(name)` отдаёт объявленное имя,
найденное **тем же поиском, каким ищется всякое написанное имя**. Ступени три:
область видимости текущего файла (§4.8), голое имя в таблице, единственное
объявление с таким последним сегментом. Третья ступень нужна тем, кто
спрашивает после элаборации, когда область уже свёрнута, — понижению и машине.

Ветка **не расширяет поверхность**. Она не вводит ни формы, ни ключевого
слова, ни неявного подключения; она заставляет соглашение §4.3 подчиняться
правилу видимости §4.8, которое сегодня обходит.

### Что правится

| Место | Что |
|---|---|
| `adamas-core/src/sig.rs` | новый `Signature::convention` |
| `adamas-core/src/term.rs` | `short` — последний сегмент имени, одна запись на всех |
| `adamas-core/src/check.rs` (`declared`) | `Bool`, `Flat` и `Primitive` ищутся соглашением |
| `adamas-core/src/check.rs` (`constant`) | голый `True`/`False` из δ-свёртки — вторым заходом |
| `adamas-core/src/pattern.rs` (`verdict`, `literal`) | имя семейства и сверка конструкторов последним сегментом |
| `adamas-core/src/eval.rs` (`try_eliminate_case`) | ветвь по последнему сегменту для двух имён соглашения |
| `adamas-core/src/total.rs` | пол ветви `False` — по последнему сегменту |
| `adamas-codegen/src/lower.rs` | теги `True`/`False` — соглашением |

**Восемь мест, семь файлов.** Молча новую форму не принимает ни одно: каждое
либо находит объявленное имя, либо отказывает прежним текстом. Проверено
мутантами (раздел 10).

### Что заработало

Программа из трёх файлов, где `Bool` объявлен в одном модуле, сравнение и
литеральный паттерн живут во втором, а считает третий, — она стоит в корпусе
(`tests/golden/eval/library.adamas`, `Cmp/Truth.adamas`, `Cmp/Words.adamas`) и
отвечает `{big = 1, small = 0, zero = 100, one = 200, other = 7}`.

Библиотечный модуль **проверяется в одиночку**: `adamas check
tests/golden/eval/Cmp/Words.adamas` — «проверено, файлов 2, объявлений 7». Это
и есть то, чего не было: до 188 модуль со сравнением проверялся только внутри
хозяина, объявившего `Bool` выше строки `import`.

Обе формы библиотеки работают, и это важно порознь: модуль вправе объявить
**свой** `Bool` (тогда он `Lib.Cmp.Bool`, и вход подключает его импортом) и
вправе **подключить чужой** (тогда он `Std.Prelude.Bool`). Ветка (а) вторую
форму запрещает, а первую делает неэкспортируемой.

### Найденная по ходу яма, закрытая там же

δ-свёртка сравнения живёт в `adamas-core::eval` и сигнатуры **не видит**:
`ltUInt64 10 20` сводится в конструктор, названный голым `True`. Перепроверка
группы (`Signature::recheck_group`) идёт по нормальной форме, и при `Bool` под
путём валидная программа отвергалась «определение `True` не найдено». Найдено
прогоном, а не чтением. Закрыто вторым заходом в `check::constant`, и заход
этот **сужен до двух имён**: всякое другое ненайденное имя обязано остаться
ненайденным, иначе третья ступень `convention` стала бы общей утечкой
видимости.

Названная граница, не закрытая: определительное равенство между свёрнутым
голым `True` и написанным `Cmp.Truth.True` не устанавливается — головы разные.
Программы, которой это видно, в корпусе нет, и заводить её трек не стал:
закрывается она либо сигнатурой в `eval`, либо переписыванием головы в
`conv::unfold`, и оба хода шире замера.

## 6. Ветка (г): у места употребления писать нечего

Ветка (г) предлагает автору писать `Std.Prelude.Bool` там, где он пишет
`Bool`. Она **не чинит ничего**, и это видно из самого отказа, ради которого
188 заведён:

```
несовпадение типов: ожидался `Std.Prelude.Bool`, получен `Bool`
```

Левая сторона — написанное автором, правая — то, что построил компилятор.
Квалификация у места употребления двигает **только левую**: пиши автор `Bool`
под псевдонимом импорта или `Std.Prelude.Bool` целиком, объявленное имя одно и
то же, и отказ дословно тот же. Правую же строит `check::prim_scheme`, и
написать её автору нечем: она не пишется в программе вовсе.

То же у литерального паттерна, и там ещё нагляднее: `classify 0 = …` не
содержит имени `Bool` ни в одном месте, писать квалификацию негде физически.
Отказ «литеральный паттерн отвечает `Bool` (§4.3), а он не объявлен» ветка (г)
не трогает.

Измерено на базе (`3261fd5`): обе формы — `Bool` под псевдонимом импорта и
`Std.Prelude.Bool` дословно — отвечают одним и тем же отказом.

## 9. Пять ответов

### 9.1 Сколько мест правится и сколько принимают новую форму молча

| (в) | 1 строка отказа плюс встроенное объявление | ничего: всё, что ломается, ломается громко |
| (г) | 0 | — (ветка ничего не чинит) |
| (д) | **8** мест, 7 файлов | ничего: каждое либо находит объявленное имя, либо отказывает прежним текстом |

Дешевизна правки доводом **не служит**, и это третий подряд случай: (а)
дешевле всех и хуже всех, потому что её единственная строка отменяет правило
видимости молча.

### 9.2 Программа, объявляющая свой `Bool` и не желающая прелюдного

Сегодня это законно, и так пишет **весь корпус**: 54 фикстуры из 116 в `eval`,
59 в `programs`/`errors`.

* **(а)** — законно, пока `Bool` объявляет **ровно один** файл программы.
  Второй отвергается «определение `Bool` уже существует», причём отказ
  показывается в том файле, который объявил вторым, а не в том, из-за которого
  столкновение. Плюс запрет на посторонний конструктор с именем `True`.
* **(б)** — ломает, и **молча**: собственное объявление остаётся в таблице, но
  всякое написанное `Bool` уезжает в прелюдное (§2). Громко ломается только
  сравнение, и текст отказа при этом говорит не о том — «ожидался
  `Std.Prelude.Bool`, получен `Bool`» при единственном написанном `Bool` в
  файле.
* **(в)** — ломает громко и целиком: имя занято языком, `data Bool` отвергается
  наравне с `data Array`.
* **(д)** — не ломает ничего. Свой `Bool` остаётся своим; два `Bool` в одной
  программе различаются, и несовпадение ловится на границе: «ожидался `Bool`,
  получен `Lib.Cmp.Bool`» — то же правило, каким §4.8 различает два `Map`.

### 9.3 Литеральный паттерн и `if`

**`if` задет не был, и это расхождение с постановкой.** Он разбирается в
`case` по написанным `True`/`False` (`expr.rs::conditional`), а написанные
имена идут через область видимости §4.8 — значит квалификация им не помеха.
Прогон: библиотечный модуль со своим `Bool` и телом `pick b x y = if b then x
else y` проверяется на базе `3261fd5` без правок.

**Литеральный паттерн задет, и сильнее сравнения.** Сравнение отказывает
несовпадением типов, у которого есть хотя бы левая сторона; литеральный
паттерн отказывает «`Bool` … не объявлен», а имени `Bool` в такой клаузе не
написано вовсе — автору нечего исправлять. Обе формы чинит (д); (а) чинит обе
ценой §9.2; (б) и (г) не чинят ни одной.

### 9.4 Однофайловая программа

Корпус `eval` — 116 фикстур, из них подключают что-либо три (`prelude`,
`zlib`, новая `library`), прочие однофайловые.

* **(д)** — не двигает ни одну: в однофайловой программе `scope.own` пуст и
  импортов нет, так что первая ступень `convention` молчит, а вторая отдаёт то
  же голое имя, что отдавал `lookup`. Гейт это и показывает.
* **(а)** — не двигает однофайловые тоже, но валит три многофайловых и
  корпусный проект.
* **(б)** — двигает **все**: прелюдия в корпусе лежит рядом
  (`tests/golden/eval/Std/Prelude.adamas`), и неявный импорт сработает у
  каждой.
* **(в)** — валит все, кто объявляет `Bool` сам.

### 9.5 Ordered scoping и неявное подключение

Вопрос к ветке (б), и ответ на него у неё **есть только вместе со вторым
решением**.

Естественная позиция неявного импорта — «до первой строки файла»: он обязан
заслоняться всем, что файл объявит сам, ровно как §4.8 требует от ordered
scoping («побеждает ближайшее объявленное»). Но сегодня порядок работает
наоборот (§2): псевдоним импорта заслоняет объявление, написанное **ниже**, и
`Scope` порядка текста не помнит вовсе. Значит (б) не сводится к одной точке
вставки: она требует, чтобы `Scope` начал различать «объявлено выше импорта» и
«объявлено ниже», то есть правки того самого механизма, на который §4.8
ссылается как на готовый.

Второй половиной вопроса — а какой модуль подключается неявно? — 188 не
занимается вовсе. Имя `Std.Prelude` сегодня не значит ничего: манифест (§7.1)
поля прелюдии не имеет, корень проекта задаёт `root`, а корпус `eval` — сотня
самостоятельных программ в одном каталоге. Ветка (б) вводит, стало быть, и
новое поле манифеста, и правило «что делать, когда прелюдии нет».

## 11. Рекомендация

**Рекомендация, а не решение.** Выбор здесь за владельцем: 188 записан
вопросом, и четыре его ветки — про поверхность языка.

Рекомендуется **(д)**, и довод у неё один, зато не про цену: это единственная
ветка, которая ничего к языку **не добавляет**. §4.3 уже говорит, что `Bool` —
имя программы, взятое по соглашению; §4.8 уже говорит, как ищется написанное
имя. (д) сводит первое ко второму и тем закрывает вопрос «в каком пространстве
имя ищется» ответом «в том же, в каком всякое другое». Прецедент в дереве уже
есть — `Signature::unit`, — и он на ту же задачу.

Прочие ветки language surface **расширяют**: (а) отменяет правило видимости для
трёх имён, (б) вводит неявное подключение вместе с полем манифеста и правилом
порядка, (в) занимает три имени языком. (г) не расширяет ничего и не чинит
ничего.

Цена (д) названа и не скрыта: восемь мест вместо одного, сверка последнего
сегмента в четырёх из них и одна незакрытая граница — определительное
равенство свёрнутого `True` с написанным `Cmp.Truth.True`.

### Что остаётся открытым помимо 188

Два расхождения, найденные по ходу, треком **не** лечатся и 188 не
принадлежат. Оба — про §4.8, и оба измерены:

1. **Верхнеуровневые имена входного файла видны внутри подключаемых модулей**
   (раздел 1). Это делает библиотеку не самостоятельной и объясняет, почему
   `zlib.adamas` собирается сегодня. Закрой утечку — и корпус упрётся в неё
   там, где сейчас зелен.
2. **Псевдоним импорта заслоняет собственное объявление, написанное ниже**
   (раздел 2), вопреки ordered scoping §4.8. От этого зависит цена ветки (б), и
   без него она не считается вовсе.
